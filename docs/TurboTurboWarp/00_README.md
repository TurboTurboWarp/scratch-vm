# TurboTurboWarp (TTW) コンパイラ設計書

対象: `TurboWarp/scratch-vm` (commit `0cb82afe`, 2026-10-31) の `src/compiler/*` と `src/engine/{sequencer,thread,runtime}.js`。
各パート (`01`〜`09`) は 1 エージェントが単独で実装できる単位。**実装順は `09_phases.md`**。

## 0. 先に結論（正直な到達見込み）

実機計測 (Node 22 / V8 12.4、`bench/` に再現コード同梱) の結果:

| ワークロード | TW 現行 | TTW 方式(手書き試作) | 倍率 | 根拠 |
|---|---|---|---|---|
| スカラー演算のみ (mandel) | 33.5 ms | 16.5 ms | **2.0〜2.6x** | これが物理上限。ネイティブ相当(3.7ns/iter) |
| 再帰 (fib 30) | 20.9 | 8.4 | 2.5x | 直接呼出し+引数型推論 |
| 手続き呼出し+mod | 41.1 | 8.3 | 5.0x | インライン化+整数 mod 高速路 |
| 数値リスト (sieve) | 41.9 | 11.0 | 3.8x | TList |
| リスト sort | 12.5 | 4.9 | 2.6x | ループ版分け |
| 文字列数値リスト (strlist) | 20.1 | 3.1〜3.5 | 5.8〜6.3x | ロード時正規化 |
| 混在リスト (`""` 混じり, grid) | 62.9 | 8.1〜8.8 | **7.4x** | TList サイドテーブル |
| 混在リストへの数値 store (micro) | 208 ms | 6.5 ms | **32x** | PACKED_ELEMENTS 回避 |
| queue (全削除→追加) | 10.4 | 4.4 | 2.3〜3.7x | TList push |
| 3D 投影 (リスト+手続き) | 28 | 7.7 | 3.6x | インライン化+版分け |
| broadcast and wait | 2510 ns/回 (依存手続き100個で 10720 ns) | 110 ns | **23〜97x** | スレッド起動の再設計 |
| クローン 300 体の毎フレーム step | 50 ns/step | 9.4 ns | **5.3x** | ジェネレータ廃止 |

**重要**: 「全プロジェクトで 5 倍」は不可能。TW は既にスカラー浮動小数ループでネイティブの約 2 倍以内にあり、ここは 2〜2.6 倍が上限（Wasm でも同じ）。
5 倍以上が出るのは **リスト・混在リスト・文字列数値・手続き呼出し・broadcast・多クローン** が支配的なプロジェクト（重い実プロジェクトの大半）。
受け入れ基準は「TTW-Bench 全カテゴリの幾何平均 ≥ 5x、かつどのカテゴリも 1.0x を下回らない」とする（`08`）。計算カーネルだけの幾何平均は現試作で約 3〜4x、システム系 (broadcast/スレッド) を含めて 5x 超の見込み。**未検証**: ブラウザ実機・レンダラ込みの実プロジェクトでの数値。

## 1. なぜ TW は遅いか（計測で確認した原因）

1. **変数が常にヒープ上** (`b0.value`)。非 Smi の double を書くたび HeapNumber を確保。
2. **リストが素の JS 配列**。文字列が 1 個でも入ると PACKED_ELEMENTS になり、数値 store ごとに確保+ライトバリア (32x 遅い)。JSON 由来の `"123"` は読むたびに文字列→数値変換。
3. **手続き呼出しが `thread.procedures["W..."](...)`**、引数は常に ANY 型でキャスト付き。
4. **スレッド起動のたびに依存手続き全部のクロージャを生成** (`tryCompile` の `result.procedures[x](this)`)。`startHats` は文字列連結キーと全スレッド走査。
5. **yield するスクリプトはジェネレータ**。resume 1 回 25ns、`yield*` は深さに比例。
6. 型解析がスクリプト内・yield でリセット。引数・戻り値・リスト要素は常に ANY。

## 3. 不変条件（全パート共通・破ってはいけない）

- I1 観測可能な値は TW と同一（数値/文字列/真偽の区別を含む）。唯一の例外は `03 §6` のロード時正規化（TW の定数変換と同じ規則）。
- I2 外部コード（拡張・GUI・モニター・クラウド）が走れるのは **セーフポイント**（yield、互換レイヤ呼出し、スレッド step の外）だけ。セーフポイントでは全状態が「ホーム」(`Variable.value` / `TList` / フレームスロット) にある。
- I3 コンパイル失敗時は TW と同じくインタプリタへフォールバック。
- I4 既存テスト (`test/integration`, `test/snapshot` の execute フィクスチャ) の実行結果が変わらない。スナップショットの JS 文字列は当然変わるので再生成する。
